# Contexto de Tarea: Taller de 4 Semanas para Construir la Plataforma

Última actualización: 2026-05-21

## Fuente Usada

Este archivo se construye a partir de la conversación de WhatsApp en:

- `workshop-platform/context/scr1.png`
- `workshop-platform/context/scr2.png`

No se usa `workshop-platform/context/CONTEXT_CURRENT_PLAT.md` como fuente para esta tarea.

## Pedido Principal

Crear un plan de taller de aproximadamente 4 semanas para enseñar a construir una plataforma desde cero, paso a paso.

El objetivo no es solamente presentar, explicar o demostrar una plataforma ya hecha. La conversación aclara que se debe enseñar a hacerla:

- "mostrar no: enseñar"
- "te repito tienes q enseñar a. hacer"
- "paso a paso"

Por tanto, el resultado esperado es un curso/taller práctico donde los participantes terminen entendiendo y construyendo las partes principales de la plataforma.

## Audiencia

La propuesta debe estar dirigida a un perfil técnico pequeño:

- Un ingeniero de sistemas.
- Un par de tecnólogos.

La conversación pide dejar claro a quién va dirigido el curso. El nivel debe asumir capacidad técnica básica o intermedia, pero no conocimiento previo profundo de la plataforma.

## Duración

La conversación menciona un plan para "unas tres o cuatro semanas" y luego se interpreta que, al ser para enseñar a hacer, puede ser "más 2 semanas". Para cerrar una propuesta clara, la tarea actual pide estructurarlo como taller de 4 semanas.

La duración debe permitir:

- Introducir el objetivo de la plataforma.
- Preparar ambiente, herramientas y dependencias.
- Construir el backend paso a paso.
- Construir el frontend paso a paso.
- Integrar sensores o simuladores.
- Probar flujos completos.
- Dejar una entrega funcional y explicable.

## Enfoque del Taller

El taller debe ser práctico y progresivo. Cada semana debe tener:

- Objetivo claro.
- Temas principales.
- Actividades guiadas.
- Entregable verificable.
- Requisitos de software, hardware o datos.

Debe evitar quedarse en teoría. La estructura debe llevar a los participantes desde una base inicial hasta una plataforma funcional.

## Alcance Esperado

El plan debe cubrir la construcción de una plataforma de monitoreo o sensado paso a paso, sin depender de que los asistentes ya sepan cómo está hecha.

El taller debe incluir, como mínimo:

- Visión funcional de la plataforma.
- Arquitectura general.
- Preparación del ambiente de desarrollo.
- Base de datos o persistencia.
- API/backend.
- Frontend o interfaz de usuario.
- Flujo de datos desde una fuente externa o sensor/simulador.
- Visualización de información.
- Pruebas básicas.
- Despliegue o ejecución local.
- Cierre con demostración final.

## Aspectos que Deben Quedar Claros

La conversación pide incluir "q más necesitarás, sw, hw..." y "a quién va dirigido". Por eso el documento final del taller debe dejar explícito:

- Público objetivo.
- Conocimientos previos requeridos.
- Software necesario.
- Hardware necesario, si aplica.
- Datos o insumos necesarios.
- Duración por semana o sesión.
- Resultado esperado al final de cada semana.
- Resultado final del taller.
- Qué parte se enseña conceptualmente y qué parte se construye en práctica.

## Propuesta de Estructura de 4 Semanas

### Semana 1: Fundamentos y Preparación

Objetivo: que los participantes entiendan qué se va a construir y dejen listo el entorno de trabajo.

Contenido sugerido:

- Propósito de la plataforma.
- Roles de frontend, backend, base de datos y fuente de datos.
- Revisión del flujo completo esperado.
- Instalación de herramientas.
- Configuración del repositorio o proyecto base.
- Ejecución local inicial.
- Primer endpoint o módulo mínimo.

Entregable:

- Ambiente funcionando.
- Proyecto base ejecutándose localmente.
- Primer flujo mínimo probado.

### Semana 2: Backend, Datos y Servicios

Objetivo: construir la capa que recibe, valida, guarda y expone información.

Contenido sugerido:

- Diseño de entidades principales.
- Base de datos y migraciones.
- API REST.
- Recepción de datos desde sensor, simulador o cliente de prueba.
- Consultas históricas.
- Manejo básico de errores.
- Documentación o pruebas de endpoints.

Entregable:

- Backend funcional.
- Base de datos con tablas principales.
- Endpoints probados para crear, consultar y recibir datos.

### Semana 3: Frontend e Integración

Objetivo: construir la interfaz que permite operar y visualizar la plataforma.

Contenido sugerido:

- Estructura de la aplicación frontend.
- Pantallas principales.
- Consumo de API.
- Visualización de estado, datos y resultados.
- Formularios de configuración.
- Integración con backend.
- Actualización de datos en vivo si aplica.

Entregable:

- Frontend funcional conectado al backend.
- Flujo de usuario principal implementado.
- Visualización de datos reales o simulados.

### Semana 4: Flujo Completo, Pruebas y Entrega

Objetivo: cerrar una versión funcional y enseñar cómo validarla, presentarla y continuarla.

Contenido sugerido:

- Integración end-to-end.
- Pruebas manuales y automáticas básicas.
- Corrección de errores comunes.
- Despliegue local o en servidor.
- Preparación de una demostración final.
- Documentación mínima para operar y extender la plataforma.
- Recomendaciones de continuidad.

Entregable:

- Plataforma funcionando de punta a punta.
- Guía de ejecución.
- Demo final preparada.
- Lista de mejoras futuras.

## Insumos por Definir

Antes de escribir el plan final del taller, se deben confirmar o completar:

- Nombre exacto de la plataforma o versión que se va a enseñar.
- Si se usará hardware real o simulador.
- Cantidad de sesiones por semana.
- Duración de cada sesión.
- Modalidad: presencial, remota o mixta.
- Sistema operativo esperado de los participantes.
- Nivel real de experiencia del ingeniero y los tecnólogos.
- Alcance de despliegue: local, servidor interno o nube.
- Si el taller debe terminar con certificación, informe, repositorio o demo formal.

## Criterio de Éxito

El taller será exitoso si, al final de las 4 semanas, los participantes pueden:

- Explicar la arquitectura de la plataforma.
- Levantar el entorno de desarrollo.
- Construir o modificar el backend.
- Construir o modificar el frontend.
- Conectar datos de prueba, simulador o sensor.
- Ejecutar un flujo completo.
- Diagnosticar errores básicos.
- Presentar una demo funcional.
- Continuar el desarrollo sin depender totalmente del instructor.

## Tono de la Propuesta

La propuesta debe sonar como un plan profesional para una entidad externa, pero con enfoque práctico. Debe explicar con claridad que no se trata de una charla ni de una muestra rápida, sino de un taller guiado para que un equipo técnico aprenda a construir la plataforma paso a paso.
